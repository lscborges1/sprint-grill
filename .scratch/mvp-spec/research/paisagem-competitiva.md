# Paisagem competitiva: refinamento de backlog / spec assistidos por IA (2024–2026)

> Research para a ferramenta self-hosted de refinamento de User Stories ("grelhar" a US com perguntas, registrar decisões, gerar spec técnica e tasks, ancorada no código da squad, integrada ao Azure DevOps). Fontes primárias citadas por afirmação. Data da pesquisa: 2026-08-05.

## Quadro comparativo

| Produto | O que faz (relevante ao problema) | Onde roda | Preço (público) |
|---|---|---|---|
| **Atlassian Rovo / Jira AI** | "Work breakdown" (quebra work items em tasks com resumo/descrição em um clique), reescrita de descrições, criação de work items via chat, agentes atribuíveis; inclui um **"Work Readiness Checker Agent"** que checa se o trabalho está claro/completo antes do planejamento. | SaaS Atlassian Cloud (Jira) | Incluído nos planos Cloud (Premium/Enterprise desde abr/2025, Standard depois); antes US$ 20/usuário/mês anual, US$ 24 mensal; modelo migrando para créditos/consumo. |
| **GitHub Copilot + Azure Boards** | Integração oficial (preview privado 2025 → caminho para GA): a partir de um work item do Azure Boards, envia a tarefa ao **Copilot coding agent**, que cria branch, gera código e abre draft PR, com progresso rastreado no work item. Foco em *executar* o item, não em refiná-lo. **Só funciona com repositórios GitHub — Azure Repos não é suportado.** | GitHub + Azure DevOps (SaaS) | Requer licença Copilot (coding agent em planos pagos do Copilot). |
| **Azure DevOps – extensões de marketplace** (AI Work Item Assistant, Copilot4DevOps, Story Reviewer) | Geram/refinam user stories, critérios de aceite e test cases dentro do Boards via Azure OpenAI; "Elicit" do Copilot4DevOps gera stories a partir do item pai. Nenhuma lê o código dos repositórios da squad. | Extensão dentro do Azure DevOps | Variado por extensão (freemium/pago). |
| **Linear AI** | **Product Intelligence** (ago/2025, preview): triagem por IA, detecção de duplicatas/relacionados, sugestão de assignee/labels/projeto. **Linear for Agents** (mai/2025) + **Linear Agent** (beta mar/2026): agentes de código como usuários de primeira classe, atribuíveis a issues. | SaaS (Linear) | Agent/Skills em todos os planos; Automations e Code Intelligence em Business/Enterprise. |
| **Notion AI** | Agente geral de escrita/pesquisa no workspace: rascunho de PRDs/specs a partir de docs, Custom Agents (set/2025), busca enterprise. Sem noção de backlog ágil nem de código. | SaaS (Notion) | AI completa no plano Business (US$ 20–24/usuário/mês); Custom Agents medidos por créditos (US$ 10/1.000 créditos). |
| **ChatPRD** | Assistente "CPO on demand": gera e critica PRDs a partir de input mínimo, coaching em tempo real, metas/métricas; integra com Notion, Linear e Google Docs (não Azure DevOps). É o mais próximo do "grill" — mas grelha o *documento*, sem contexto do código. | SaaS | Basic US$ 8/mês; Pro US$ 15/mês; Team US$ 24/usuário/mês; Enterprise sob consulta. |
| **Amazon Kiro** | IDE agêntico spec-driven (GA mar/2026, Claude via Bedrock): specs → user stories em formato EARS → design técnico (interfaces TS, endpoints, schemas) → tasks, com rastreabilidade; usa o codebase existente. Fluxo dev-cêntrico dentro do IDE, sem PO no loop e sem tracker ágil. | IDE desktop (Code OSS) | Free 50 créditos; Pro US$ 20, Pro+ US$ 40, Pro Max US$ 100, Power US$ 200/usuário/mês (créditos). |
| **GitHub Spec Kit** | Toolkit open source (MIT) de spec-driven development: `/speckit.specify`, **`/speckit.clarify` (perguntas de esclarecimento)**, `/plan`, `/tasks`, `/implement`, `/converge`; funciona com 30+ agentes (Copilot, Claude Code etc.). Roda no repo, então *é* ancorado no código — mas é CLI para dev, sem UI para Produto, sem integração com tracker. | CLI local (`specify init`) dentro do repo | Gratuito (open source, MIT). |
| **Tessl / OpenSpec / BMAD** | Onda SDD 2025: Tessl lançou Framework + Spec Registry (set/2025) e **repivotou para "agent skills" em jan/2026**; OpenSpec e BMAD são workflows SDD open source usados via MCP/CLI. | CLI / MCP | Registry Tessl gratuito; OSS. |
| **Spinach.ai** | "AI Scrum Master": entra nas reuniões (refinement, planning, standup), resume decisões, sugere tickets novos e updates no Jira. Captura a *conversa*, não conduz o refinamento nem conhece o código. | SaaS + app Atlassian Marketplace | Freemium/pago por usuário. |

## Quem tentou e falhou/pivotou

- **Height.app** — PM tool "AI-native"; lançou o Height 2.0 "autonomous project collaboration" (out/2024) com triagem de bugs, poda de backlog e **specs auto-atualizadas**; anunciou shutdown em 20/mar/2025 e fechou em 24/set/2025. Análises apontam custo de inferência embutido vs. disposição a pagar US$ 7–12/usuário/mês como fator do fracasso. Lição: IA autônoma de PM como *produto horizontal pago por assento* não fechou a conta; uso interno self-hosted não tem esse problema. Fontes: [Creativerly](https://www.creativerly.com/height-app-is-shutting-down/), [AlternativeTo](https://alternativeto.net/news/2025/3/height-project-management-tool-to-shut-down-by-september-2025/), [Skywork](https://skywork.ai/skypage/en/Height-App-The-Rise-and-Sunset-of-an-AI-Project-Management-Pioneer/1975012339164966912).
- **Tessl** — evangelista original de "spec as source"; em jan/2026 reposicionou de specs para agent skills (Spec Registry → Tessl Registry). Sinal de que "spec como artefato central vendável" é difícil como produto standalone. Fontes: [Tessl blog](https://tessl.io/blog/tessl-launches-spec-driven-framework-and-registry/), [CodeMySpec landscape](https://codemyspec.com/blog/best-spec-driven-development-tools).

## Onde está o vão

Ninguém cobre o ciclo completo **US crua → interrogatório HITL → decisões registradas → spec técnica → tasks no Azure DevOps**, ancorado no código real da squad e com Produto no loop:

1. **Refinamento ancorado no código é exclusividade das ferramentas dev-cêntricas.** Kiro e Spec Kit leem o codebase e até fazem perguntas de esclarecimento (`/speckit.clarify`), mas rodam em IDE/CLI: PO/PM não participa, e nada volta para o tracker como decisão registrada. Fontes: [spec-kit](https://github.com/github/spec-kit), [Forbes/Kiro](https://www.forbes.com/sites/janakirammsv/2025/07/15/aws-launches-kiro-a-specification-driven-agentic-ide/), [kiro.dev/pricing](https://kiro.dev/pricing/).
2. **As ferramentas de PM/PO não enxergam o código.** Rovo (Work Readiness Checker, work breakdown), ChatPRD e Notion AI refinam texto contra texto — o "está maduro?" é julgado sem saber o que o sistema já faz, quais contratos existem, o que é caro de mudar. Fontes: [atlassian.com/software/jira/ai](https://www.atlassian.com/software/jira/ai), [chatprd.ai/pricing](https://www.chatprd.ai/pricing).
3. **No ecossistema Azure DevOps o vão é maior ainda.** A única integração de agente da Microsoft (Boards + Copilot coding agent) pula o refinamento — vai de work item direto a código — e **exige repositório no GitHub, não suporta Azure Repos**. As extensões de marketplace geram stories/ACs genéricos sem contexto de repositório. Fontes: [devblogs Azure Boards + Copilot](https://devblogs.microsoft.com/devops/azure-boards-integration-with-github-copilot-private-preview/), [MS Learn](https://learn.microsoft.com/en-us/azure/devops/boards/github/work-item-integration-github-copilot?view=azure-devops).
4. **Ninguém registra o interrogatório como artefato.** O valor das skills grill-with-docs/to-spec/to-tickets é o log de perguntas → respostas → decisões que vira insumo da spec. Rovo checa prontidão (checklist), Spinach resume reunião, mas nenhum conduz o Q&A socrático nem persiste as decisões vinculadas à US.
5. **Self-hosted/privacidade.** Todas as opções de PM são SaaS; só as CLIs SDD rodam local. Não há produto self-hosted que combine UI de refinamento HITL para Produto + contexto de código + escrita de work items no Azure DevOps.

**Vão identificado:** um "griller" HITL que fica *entre* o Azure Boards e os repositórios da squad — interroga a US com perguntas geradas a partir do código e dos docs, com PO respondendo numa UI simples, registra decisões, e só então gera spec e tasks de volta no Azure DevOps. É a combinação (código ⊗ Produto-no-loop ⊗ Azure DevOps ⊗ self-hosted) que nenhum player cobre; os grandes cobrem cada eixo isoladamente.
